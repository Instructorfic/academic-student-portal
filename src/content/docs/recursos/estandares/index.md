Conjunto normativo que define **cómo se construye el software** de los
proyectos de las materias, con independencia del equipo o integrante que lo
escriba. Su principio rector es *"primero consistencia, después calidad,
después optimización"*.

Es un **recurso transversal**: aplica a cualquier materia con proyecto de
software real, como Taller Integrador de Especialización, Gestión de
Seguridad y Desempeño de Bases de Datos o Pruebas de Software. Para tu
equipo es la referencia única de las reglas de código, control de
versiones, revisión, pruebas, seguridad y entrega.

Estos documentos son normativos para la **construcción del software**, no
para el currículo: no sustituyen el programa de ninguna materia. Si el
handbook es obligatorio o una referencia recomendada en tu materia lo
indica tu docente.

## Prioridades y niveles

Cada regla tiene una **prioridad** (P0 crítico, P1 obligatorio, P2
importante, P3 mejora) y un **nivel de exigencia** (OBLIGATORIO,
RECOMENDADO, AVANZADO). El detalle está en el
[documento 00](/recursos/estandares/00-indice-y-arquitectura-documental/), secciones D y siguientes. Si solo puedes leer
una página, empieza por las [20 reglas de oro](/recursos/estandares/17-reglas-de-oro/).
