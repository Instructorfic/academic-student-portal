## Dónde estamos dentro del taller

```text
Bloque I    Del problema al producto        ← estás aquí
Bloque II   Colaboración y arquitectura
Bloque III  Construcción del sistema
Bloque IV   Contenedores despliegue y escalabilidad
Bloque V    Integración y presentación final
```

El proyecto comienza a organizarse desde este bloque: no se espera
hasta el final del semestre para descubrir qué se debe construir.

> **Idea central.** Primero entendemos el problema. Después organizamos
> el trabajo. Luego construimos incrementos funcionales.

## El problema no es la solución

```text
Situación actual
Los estudiantes necesitan acudir personalmente al área responsable
para saber si un equipo está disponible.

Problema
No existe un medio centralizado para consultar en tiempo real qué
equipos están disponibles, ocupados o en mantenimiento.

Consecuencia
Los estudiantes realizan traslados y consultas innecesarias y pueden
retrasar sus actividades.

Necesidad
Contar con información actualizada sobre la disponibilidad de los
equipos.

Solución posible
Un sistema web que permita consultar la disponibilidad de los equipos
y enviar solicitudes de préstamo.
```

Primero se entiende el problema. Después se define la solución. Este
recorrido completo (situación → problema → necesidad → solución) se
explica con detalle en
[1. El desarrollo profesional de software](/materias/taller-integrador/bloque-01/01-desarrollo-profesional-de-software/).

**Evita comenzar por la tecnología.** Una solución técnicamente
interesante no necesariamente resuelve un problema real.

## La idea central de Scrum

```text
01 PLANEAR      qué construir
02 CONSTRUIR    un incremento
03 REVISAR      el resultado
04 APRENDER     lo que arrojó la revisión
05 ADAPTAR      el siguiente paso
06 NUEVO INCREMENTO
```

No se intenta predecir todo desde el primer día: se construye, se
revisa y se aprende mediante incrementos. Ver
[3. Introducción a Scrum](/materias/taller-integrador/bloque-01/03-introduccion-a-scrum/)
para el detalle de roles, artefactos y eventos.

## Del problema al Product Backlog

```text
01 Problema   02 Usuarios   03 Necesidades   04 Historias de usuario
05 Criterios de aceptación   06 Prioridad   07 Estimación   08 Product Backlog
```

Primero se comprende el problema y las necesidades. Después se
transforma ese conocimiento en elementos que pueden formar parte del
Product Backlog. Ver
[4. Definición del proyecto](/materias/taller-integrador/bloque-01/04-definicion-del-proyecto/).

## El proyecto ya debe tener dirección

Antes de este bloque: "Tenemos un proyecto." Al cerrarlo:

```text
Tenemos un problema definido
        ↓
Tenemos usuarios identificados
        ↓
Tenemos un alcance
        ↓
Tenemos historias
        ↓
Tenemos un Product Backlog
        ↓
Tenemos un equipo organizado
        ↓
Tenemos una primera funcionalidad
```

## Cierre

> Un buen proyecto no comienza escribiendo código. Comienza entendiendo
> el problema, organizando el trabajo, definiendo qué significa
> entregar valor, y construyendo un primer incremento que pueda
> demostrarse.
