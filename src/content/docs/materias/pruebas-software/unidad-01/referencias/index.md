## Cómo usar este documento

Una relevancia "Baja" no significa que la obra carezca de valor:
significa que su aporte principal corresponde a otra unidad de la
materia o que su enfoque es demasiado específico para el nivel
introductorio de esta unidad.

## Bibliografía básica

### Myers, Sandler y Badgett — *The Art of Software Testing*

| Campo | Valor |
| --- | --- |
| Autores | Glenford J. Myers, Corey Sandler, Tom Badgett |
| Edición | 3.ª edición |
| Editorial | Wiley |
| Año | 2011 |
| Relevancia para esta unidad | Alta |

Obra clásica de referencia para la psicología y los objetivos de las
pruebas de software, útil como fundamentación conceptual de por qué
se prueba. Relacionada con
[3. Propósito de las pruebas de software](/materias/pruebas-software/unidad-01/03-proposito-de-las-pruebas/)
y [4. Principios generales de pruebas](/materias/pruebas-software/unidad-01/04-principios-generales-de-pruebas/).

| Autor | Paul C. Jorgensen |
| Edición | 4.ª edición |
| Editorial | CRC Press |
| Año | 2013 |
| Relevancia para esta unidad | Alta |

## Estándares y referencias técnicas

### ISO/IEC/IEEE 29119

| Campo | Valor |
| --- | --- |
| Referencia | ISO/IEC/IEEE 29119 — Software Testing Standards (partes 1 a 5) |
| Relevancia para esta unidad | Media |

La Parte 1 (conceptos y definiciones) es la más pertinente a este
nivel introductorio, como referencia conceptual y de vocabulario
normalizado. Las partes sobre procesos de prueba, documentación y
técnicas corresponden a la Unidad III y posteriores.

### ISO/IEC 25010:2011

| Campo | Valor |
| --- | --- |
| Referencia | ISO/IEC 25010:2011 — Systems and Software Engineering, Quality Models |
| Relevancia para esta unidad | Alta |

Modelo de calidad de referencia directamente pertinente a
[1. Calidad de software](/materias/pruebas-software/unidad-01/01-calidad-de-software/):
útil para dar una definición formal y verificable de "características
de calidad", en lugar de una definición informal.

### IEEE 829-2008

| Campo | Valor |
| --- | --- |
| Referencia | IEEE 829-2008 — Standard for Software and System Test Documentation |
| Relevancia para esta unidad | Baja |

Estándar de documentación de pruebas (planes, casos, reportes). Su
relevancia principal corresponde a la Unidad III.

## Ampliación — panorama normativo internacional

> El programa oficial cita ISO/IEC 29119, IEEE 829 e ISO/IEC 25010.
> Esta ampliación agrega el resto de la familia 29119 y tres normas
> relacionadas, para dar un panorama más completo del ecosistema de
> estándares de la disciplina. No cambia lo que se evalúa en RA1.1–RA1.4.

| Estándar | Categoría | Alcance | Relevancia en esta unidad |
| --- | --- | --- | --- |
| ISO/IEC/IEEE 29119-2 | Gobernanza y gestión | Ciclo de vida del testing basado en riesgos | Media |
| ISO/IEC/IEEE 29119-3 | Aseguramiento documental | Planes, casos e informes de prueba | Baja (Unidad III) |
| ISO/IEC/IEEE 29119-4 | Ejecución técnica | Técnicas de caja negra, caja blanca | Baja (Unidad III) |
| ISO/IEC/IEEE 29119-5 | Automatización | Pruebas dirigidas por palabras clave | Baja (Unidad IV) |
| ISO/IEC TR 29119-6 | Adaptabilidad metodológica | Uso de la 29119 en proyectos ágiles | Baja (mención contextual) |
| ISO/IEC TR 29119-11 | Tecnologías emergentes | Pruebas de sistemas basados en IA | Baja (mención contextual) |
| ISO/IEC/IEEE 12207 | Ciclo de vida | Integra verificación y validación en la ingeniería de software | Media |
| ISO/IEC 20246 | Verificación temprana | Revisión de código, diagramas y requerimientos | Media |
| ISO/IEC 33000 | Auditoría de capacidad | Madurez de los procesos de un equipo de QA | Baja |
