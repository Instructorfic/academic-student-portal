**RA relacionado:** RA1.2. **Contenido:** 1.2.1, 1.2.2. **Modalidad:**
individual o pareja.

## Contexto

A partir de [3. Propósito de las pruebas de software](/materias/pruebas-software/unidad-01/03-proposito-de-las-pruebas/)
(propósito de las pruebas y pruebas como reducción de riesgo) y del
sistema bajo prueba que elegiste para tu proyecto integrador.

## Instrucciones

1. Enumera entre cuatro y seis funcionalidades o componentes de tu
   sistema bajo prueba.
2. Para cada uno, estima de forma cualitativa (alto/medio/bajo):
   - su **impacto** si llegara a fallar (por ejemplo, si afecta una
     operación crítica o una funcionalidad secundaria)
   - su **probabilidad** de fallo (por ejemplo, por su complejidad,
     por ser nuevo, o por depender de servicios externos)
3. Ordena las funcionalidades de mayor a menor riesgo combinando
   impacto y probabilidad, y justifica el orden en una o dos frases
   por elemento.
4. Responde: si solo tuvieras tiempo para probar exhaustivamente una
   de esas funcionalidades antes de una entrega, ¿cuál elegirías, y
   por qué?

## Producto esperado

Tabla o lista de funcionalidades con impacto, probabilidad, prioridad
resultante y justificación.

## Criterio de logro

Identifica entre cuatro y seis funcionalidades reales de su sistema
bajo prueba, asigna impacto y probabilidad de forma razonada (no
arbitraria) y prioriza correctamente considerando ambos factores, no
solo uno de ellos.
