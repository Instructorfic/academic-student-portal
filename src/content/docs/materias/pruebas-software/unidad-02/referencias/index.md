## Cómo usar este documento

Una relevancia "Baja" no significa que la obra carezca de valor:
significa que su aporte principal corresponde a otra unidad de la
materia o que su enfoque es demasiado específico para esta unidad.

## Bibliografía básica

### Jorgensen — *Software Testing: A Craftsman's Approach*

| Campo | Valor |
| --- | --- |
| Autor | Paul C. Jorgensen |
| Edición | 4.ª edición |
| Editorial | CRC Press |
| Año | 2013 |
| Relevancia para esta unidad | Alta |

De las tres obras básicas, es la que trata con mayor formalidad la
relación entre especificación de requisitos y el proceso de prueba,
incluyendo nociones de trazabilidad. Relacionada con
[1. Requisitos funcionales, no funcionales y reglas de negocio](/materias/pruebas-software/unidad-02/01-requisitos-funcionales-no-funcionales-reglas-negocio/)
y [4. Trazabilidad y matriz de trazabilidad](/materias/pruebas-software/unidad-02/04-trazabilidad-matriz/).

### Patton — *Software Testing*

| Campo | Valor |
| --- | --- |
| Autor | Ron Patton |
| Edición | 2.ª edición |
| Editorial | Sams Publishing |
| Año | 2005 |
| Relevancia para esta unidad | Media |

Ejemplos accesibles de casos "normales" y "de error", útiles para
diseñar escenarios positivos y negativos. Relacionada con
[3. Criterios de aceptación y escenarios](/materias/pruebas-software/unidad-02/03-criterios-aceptacion-escenarios/).

### Myers, Sandler y Badgett — *The Art of Software Testing*

| Campo | Valor |
| --- | --- |
| Autores | Glenford J. Myers, Corey Sandler, Tom Badgett |
| Edición | 3.ª edición |
| Editorial | Wiley |
| Año | 2011 |
| Relevancia para esta unidad | Media |

Su enfoque central es el diseño técnico de casos de prueba (Unidad III),
pero incluye el principio de que toda prueba parte de una especificación
conocida — relevante como fundamentación de por qué los requisitos son
la base de las pruebas.

## Bibliografía complementaria

### Crispin y Gregory — *Agile Testing*

| Campo | Valor |
| --- | --- |
| Autoras | Lisa Crispin, Janet Gregory |
| Editorial | Addison-Wesley |
| Año | 2009 |
| Relevancia para esta unidad | Alta |

A diferencia de su relevancia baja en la Unidad I, aquí es una de las
fuentes más pertinentes: trata directamente historias de usuario y
criterios de aceptación desde la perspectiva del equipo ágil. Relacionada
con [2. Casos de uso e historias de usuario](/materias/pruebas-software/unidad-02/02-casos-de-uso-historias-usuario/)
y [3. Criterios de aceptación y escenarios](/materias/pruebas-software/unidad-02/03-criterios-aceptacion-escenarios/).

### Black, van Veenendaal y Graham — *Foundations of Software Testing ISTQB Certification*

| Campo | Valor |
| --- | --- |
| Autores | Rex Black, Erik van Veenendaal, Dorothy Graham |
| Editorial | Cengage Learning |
| Año | 2012 |
| Relevancia para esta unidad | Alta |

El temario ISTQB Foundation Level trata la "base de pruebas" (*test
basis* — requisitos, historias de usuario, casos de uso) y la
trazabilidad como bloques formales propios, alineados temáticamente con
toda la unidad.

### Toledo — *Introducción a las pruebas de sistemas de información*

| Campo | Valor |
| --- | --- |
| Autor | Federico Toledo |
| Editorial | Abstracta |
| Año | 2024 |
| Acceso | <https://federico-toledo.com/category/introduccion-al-testing/> |
| Relevancia para esta unidad | Media |

Única fuente de la bibliografía oficial en español y con acceso digital
directo; útil como lectura de apoyo sobre requisitos y casos de uso.
Verifica la disponibilidad del enlace antes de tomarlo como lectura
obligatoria, ya que es contenido de blog y puede reorganizarse.

## Estándares y referencias técnicas

### ISO/IEC/IEEE 29119

| Campo | Valor |
| --- | --- |
| Referencia | ISO/IEC/IEEE 29119 — Software Testing Standards (partes 1 a 5, citadas sin desglose por el programa oficial) |
| Relevancia para esta unidad | Media |

La parte con mayor pertinencia temática sería la Parte 3 (*Test
documentation*, plantillas de documentación de pruebas, incluida la
trazabilidad), pero esa correspondencia específica no está verificada
para esta unidad — el programa oficial no desglosa partes aquí.
Relacionada con
[4. Trazabilidad y matriz de trazabilidad](/materias/pruebas-software/unidad-02/04-trazabilidad-matriz/).

### ISO/IEC 25010:2011

| Campo | Valor |
| --- | --- |
| Referencia | ISO/IEC 25010:2011 — Systems and Software Engineering, Quality Models (SQuaRE) |
| Relevancia para esta unidad | Media |

El mismo modelo de calidad ya introducido en la Unidad I, aquí reutilizado
con otro propósito: dar vocabulario formal a los requisitos no
funcionales (rendimiento, seguridad, usabilidad, disponibilidad).

### IEEE 829-2008

| Campo | Valor |
| --- | --- |
| Referencia | IEEE 829-2008 — Standard for Software and System Test Documentation |
| Relevancia para esta unidad | Baja |

Estándar de documentación de pruebas (planes, casos, reportes). Su
relevancia principal corresponde a la Unidad III.
